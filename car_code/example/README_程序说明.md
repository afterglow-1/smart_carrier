# STM32H750 示例程序说明

本目录包含 16 个 Arduino/PlatformIO 风格的 `.ino` 示例，主要覆盖机械臂、底盘步进电机、串口舵机、二维码扫码、串口屏、IMU、电池电压检测和 LED 测试。

> 目标平台从代码中的 STM32 引脚命名可判断为 STM32 系列，结合当前项目背景，主要面向 STM32H750VBT6。  
> `.ino` 文件通常应单独作为 Arduino 工程主文件使用。不要把多个同时含有 `setup()` 和 `loop()` 的文件直接放入同一工程编译，否则会发生重复定义。

## 依赖库

部分示例依赖以下第三方库：

- `AccelStepper`：STEP/DIR 步进电机控制
- `TTL_STEPPER`：项目自定义的串口步进电机库
- `FashionStar_SmartGripper`：Fashion Star 总线舵机和智能夹爪控制
- `JY901`：HWT101/JY901 IMU 数据解析

使用这些示例前，需要确保相应库已安装到 PlatformIO 或 Arduino 工程中。

# 逐文件说明

## 1. `ARM.ino`

### 用途

这是一个圆柱坐标机械臂的综合动作示例，控制四个执行部分：

1. 底部旋转轴
2. 悬臂伸缩轴
3. 丝杠升降轴
4. 末端夹爪

### 硬件和接口

- 底部旋转轴：
  - 使用 `AccelStepper`
  - STEP：`PB11`
  - DIR：`PE15`
  - EN：`PE10`
- 两个串口步进电机：
  - UART RX：`PA3`
  - UART TX：`PA2`
  - 悬臂轴 ID：`6`
  - 升降轴 ID：`7`
- 总线夹爪：
  - UART RX：`PC7`
  - UART TX：`PC6`
  - 舵机 ID：`4`

### 运动参数

- 步进电机：200 脉冲/转
- 细分：16
- 底座减速比：4:1
- 丝杠导程：12 mm
- 齿轮模数：1
- 齿轮齿数：36

### 执行流程

程序启动后依次执行：

1. 底座旋转到 30°
2. 悬臂伸出 10 mm
3. 升降轴移动 10 mm
4. 夹爪闭合
5. 夹爪张开
6. 三个机械轴回到 0 位
7. 进入无限循环并停止继续动作

### 主要函数

- `rotateBase(degrees)`：将底座移动到指定角度
- `moveSmallArm(distance)`：移动齿轮齿条悬臂
- `moveBigArm(distance)`：移动丝杠升降轴
- `closeGripper()`：闭合夹爪
- `openGripper()`：张开夹爪

### 注意事项

- 程序把上电位置直接当作零位，没有限位开关或回零流程。
- 两个 TTL 步进电机的等待循环依赖 `distanceToGo()` 自动更新；需要确认自定义库是否会自行刷新状态。
- 若自定义库需要持续调用 `run()` 或读取状态，则当前等待循环可能无法退出。
- 调试前应先低速、短距离测试，避免机械碰撞。

## 2. `Battery.ino`

### 用途

这是功能较完整的电池电压监控程序，完成：

- ADC 采样
- 多次平均滤波
- 分压比例换算
- 电池电量百分比估算
- 低电量报警
- 调试串口输出
- 串口屏电压显示
- 提供校准和 JSON 输出辅助函数

### 接口

- 电池 ADC：`PC1`
- 调试串口：
  - RX：`PB12`
  - TX：`PB13`
  - 115200 baud
- 串口屏：
  - RX：`PB15`
  - TX：`PB14`
  - 115200 baud

### 默认参数

- ADC 参考电压：3.3 V
- ADC 分辨率：12 位
- 分压比：11
- 平均采样次数：10
- 读取周期：1000 ms
- 低电压阈值：3.2 V

### 运行逻辑

每秒执行一次：

1. 连续读取 10 次 ADC
2. 将 ADC 值换算为引脚电压
3. 乘以 11 倍分压比，得到原始电池电压
4. 按 3.0～4.2 V 线性估算锂电池百分比
5. 从调试串口打印电压、百分比和状态
6. 低于 3.2 V 时输出低电量警告
7. 将电压乘以 100 后写入串口屏组件 `x1.val`

### 辅助函数

- `readBatteryVoltage()`：平均采样并计算分压前电池电压
- `getBatteryPercentage()`：按单节锂电池 3.0～4.2 V 线性换算
- `displayBatteryInfo()`：打印电池状态
- `getBatteryPercentageLeadAcid()`：12 V 铅酸电池百分比估算
- `calibrateVoltage()`：连续打印读数，辅助万用表校准
- `printJsonData()`：输出 JSON 格式监控数据
- `readDirectVoltage()`：不乘分压比的直接 ADC 电压

### 注意事项

- 注释写的是 A0/PA0，但代码实际使用 `PC1`，接线应以代码为准。
- 默认百分比模型适用于单节锂电池。如果测量 12 V 电池，当前百分比结果不正确。
- `BATTERY_LOW_THRESHOLD = 3.2` 同样更像单节锂电池阈值。
- 11 倍分压比必须根据实际电阻值校准。
- STM32 ADC 引脚电压不得超过芯片允许范围。
- `while (!Serial_DEBUG)` 在普通硬件 UART 上通常没有必要，某些环境下可能导致等待行为。

## 5. `FSM_SQUARE.ino`

### 用途

使用 4 个 STEP/DIR 步进电机和有限状态机，让移动底盘依次执行：

1. 前进
2. 左移
3. 后退
4. 右移
5. 停止

整体意图是让底盘走一个方形路径。

### 接口

- 共同使能：`PE13`
- M1：DIR `PD6`，STEP `PD4`
- M2：DIR `PE9`，STEP `PE11`
- M3：DIR `PD14`，STEP `PD15`
- M4：DIR `PC3_C`，STEP `PA1`
- M5 被设置为失能：`PE10`

### 关键参数

- 每段目标脉冲：10000
- 最大速度：5000
- 加速度：2000
- 电机极性：`{-1, 1, -1, 1}`

### 状态机

- `STATE_FORWARD`
- `STATE_LEFT`
- `STATE_BACKWARD`
- `STATE_RIGHT`
- `STATE_STOP`

每个状态首次进入时设置一次相对位移；全部电机到位后切换到下一状态。

### 注意事项

- `PULSES_PER_METER` 名称暗示“每米脉冲数”，但值是否准确必须根据轮径、减速比和细分校准。
- 当前动作只执行一轮，最后停在 `STATE_STOP`。
- 代码没有回零、限位、急停和失步检测。
- 需要先确认四轮布局和正负极性是否对应实际麦克纳姆轮或全向轮安装方向。

## 7. `Gripper_Storage.ino`

### 用途

联合测试智能夹爪和旋转载物盘。

### 接口

与 `Gripper.ino` 相同：

- UART RX：`PC7`
- UART TX：`PC6`
- 115200 baud
- 夹爪 ID：4
- 载物盘 ID：5

### 载物盘角度

数组：

```cpp
int storage[4] = {-3, 9, -81, -130};
```

含义注释为：

- `storage[0]`：出发位置
- `storage[1]`：R 盘位
- `storage[2]`：G 盘位
- `storage[3]`：B 盘位

### 运行逻辑

循环执行：

1. 载物盘转到 `storage[0]`
2. 等待舵机到位
3. 张开夹爪
4. 等待 2 秒
5. 载物盘转到 `storage[3]`
6. 等待舵机到位
7. 闭合夹爪
8. 等待 2 秒

### 注意事项

- 当前只使用了出发位置和 B 盘位，R/G 盘位未使用。
- 同样存在代码注释中提到的反向供电或上电顺序风险。
- 载物盘角度必须结合实际机械零位重新标定。

## 8. `HWT101.ino`

### 用途

读取 HWT101/JY901 IMU 的 Z 轴角度，并显示到串口屏。

### 接口

- IMU 串口：
  - RX：`PD9`
  - TX：`PD8`
  - 115200 baud
- 串口屏：
  - RX：`PB15`
  - TX：`PB14`
  - 115200 baud

### 运行逻辑

1. 持续读取 IMU 串口字节
2. 使用 `JY901.CopeSerialData()` 解析
3. 读取 Z 轴角度 `Angle[2]`
4. 转换到 -180°～180°附近的浮点角度
5. 乘以 100 转为整数
6. 每 100 ms 写入串口屏变量 `x0.val`

### 显示方式

例如角度为 12.34°，发送到屏幕的是整数 `1234`，由屏幕端使用虚拟浮点方式显示。

### 注意事项

- 代码只显示角度，没有使用已声明的 `Gyro` 变量。
- 注释说读取角加速度，但实际代码没有读取角速度或角加速度。
- 串口屏命令必须以三个 `0xFF` 结束。

## 10. `Lower_ARM_STEPPER.ino`

### 用途

通过自定义 `TTL_STEPPER` 串口协议控制一个步进电机在两个位置之间往复运动。

### 接口

- UART RX：`PA3`
- UART TX：`PA2`
- 步进电机 ID：6
- 波特率：115200

### 运行逻辑

1. 上电等待 1 秒
2. 初始化串口步进协议
3. 初始化 ID 6 电机
4. 移动到位置 800
5. 等待 1 秒
6. 返回位置 0
7. 等待 1 秒
8. 重复

### 注意事项

- 注释指出默认 3200 脉冲一圈，因此 800 大约是四分之一圈，但实际取决于驱动器细分。
- 没有回零传感器，0 位是驱动器或程序当前认定的位置。

## 12. `QRCode.ino`

### 用途

从串口二维码扫描模块接收一次扫描结果，并显示到串口屏。

### 接口

- 串口屏：
  - RX：`PB15`
  - TX：`PB14`
  - 115200 baud
- 二维码模块：
  - RX：`PE0`
  - TX：`PE1`
  - 9600 baud

### 数据格式

代码按最多 7 个有效字符处理，并识别：

- `0x0D`：回车 CR，表示一帧结束
- `0x0A`：换行 LF，重置索引

示例数据注释为：

```text
321+123\r\n
```

### 运行逻辑

1. 初始化串口屏和扫码模块
2. 命令串口屏跳转到 `main` 页面
3. 在首次扫码成功前持续接收数据
4. 收到 CR 后结束字符串并设置 `scanFlag`
5. 屏幕显示：
   - `t1.txt="QROK"`
   - `t3.txt="<扫码内容>"`
6. 未扫码时只发送一次默认文本 `123+123`

### 注意事项

- 只允许成功扫描一次，之后不会再接收新二维码。
- 接收缓冲区只有 8 字节，适合 7 字符左右的短码。
- 若二维码内容更长，会被截断。
- 如果要连续扫描，应在处理后清除 `scanFlag` 和缓冲区。

## 13. `STEP1.ino`

### 用途

控制单个 STEP/DIR 步进电机进行往返位置测试。

### 接口

实际创建的电机使用：

- DIR：`PD6`
- STEP：`PD4`
- 共同使能：`PE13`

其他电机引脚虽然已定义，但没有被使用。

### 参数

- 最大速度：10000
- 加速度：10000
- 注释假定：3200 脉冲/圈

### 运行逻辑

循环执行：

1. 到 `-6400`
2. 回到 `0`
3. 到 `6400`
4. 回到 `0`

即两个方向各转约两圈，再返回零位。

### 特点

使用 `runToNewPosition()`，属于阻塞式控制，电机运动期间程序无法及时处理其他任务。

## 14. `STEP4.ino`

### 用途

同时控制 4 个 STEP/DIR 步进电机移动到固定目标位置。

### 目标位置

- M1：-6400
- M2：+6400
- M3：-6400
- M4：+6400

### 参数

- 最大速度：10000
- 加速度：2000
- M1～M4 共同使能
- M5 被主动失能

### 运行逻辑

`setup()` 中设置一次目标位置，`loop()` 中持续分别调用四个电机的 `run()`，因此四个电机可以非阻塞并行运动。

### 结果

四个电机到达目标位置后停止，不会自动往返或进入下一动作。

## 15. `STEP4_FSM.ino`

### 用途

- 使用电机极性数组适配实际安装方向

### 与 `FSM_SQUARE.ino` 的关系

两个文件内容基本一致，建议合并或只保留一个正式版本。

## 16. `TJCHMI QR.ino`

### 用途

与 `QRCode.ino` 基本相同：

- 接收二维码模块数据
- 只接受第一次成功扫码
- 将结果显示到串口屏

### 主要区别

未扫码时显示的默认文本为：

```text
111+111
```

而 `QRCode.ino` 中是：

```text
123+123
```

建议两个版本合并，并将默认内容改为配置常量。

# 已发现的潜在问题

## 1. 多个 `.ino` 不能直接放入同一 Arduino 工程

这些文件大多各自定义了 `setup()` 和 `loop()`。如果全部放在一个 PlatformIO `src` 目录中，会出现重复定义错误。

建议每个示例建立独立工程，或将功能代码重构为 `.h/.cpp` 模块，只保留一个主程序入口。

## 2. 缺少统一的引脚初始化

若干步进电机示例直接调用 `digitalWrite()`，但没有显式调用：

```cpp
pinMode(EN_PIN, OUTPUT);
```

某些 Arduino STM32 实现可能仍能工作，但建议明确设置引脚模式。

## 3. 缺少回零和限位保护

机械臂和步进示例都直接把当前位置当零点，没有：

- 原点传感器
- 限位开关
- 超时
- 堵转检测
- 急停

正式机械系统中必须补充这些保护。

## 4. 电池百分比模型可能与实际电池不匹配

当前完整电池示例使用 3.0～4.2 V 单节锂电池模型，但分压比 11 更像用于高电压电池组。需要根据实际电池类型修改：

- 满电电压
- 空电电压
- 低电量阈值
- 分压比

## 5. 二维码接收长度较短

二维码缓冲区只有 8 字节，只适合类似 `123+123` 的短数据。若二维码包含 URL、JSON 或长字符串，必须扩大缓冲区。

## 6. 串口屏刷新可能过于频繁

二维码程序在扫码成功后，每次 `loop()` 都重复发送相同屏幕命令。建议只在状态变化时发送一次，减少串口占用。

## 7. 夹爪供电存在风险提示

代码作者已记录舵机板可能通过信号线或电源线反向给 STM32 供电。应检查：

- 两块板是否共地
- 供电电压是否一致
- 是否需要串联电阻或电平转换
- 是否存在 USB 与外部电源同时供电冲突

# 建议的验证顺序

1. `LED.ino`：验证编译、无线 CMSIS-DAP 烧录和 MCU 运行
